SQLGuardian

Runbook automation for SQL Server incident response

Most monitoring tools tell you something is wrong. SQLGuardian is the layer on top: it ingests a team's own SOPs and runbooks and walks the on-call engineer through that team's process, not a generic one.

  • Seven checks (blocking, waits, Agent jobs, disk, backup age, log growth, long-running requests) each trigger the matching runbook step.
  • On a blocking chain: names the head blocker, shows the statement holding the lock, orders options by risk with KILL last.
  • Drafts the incident report from evidence already collected, the part nobody has time to write.
  • One incident, two audiences: a technical view and a plain-language summary.

SQL Estate Triage

Which stored procedures in an estate are worth an engineer's time

A linter ranks stored procedures by how bad the code looks. That is not the same as what they cost. On a 4,096-module estate the most expensive procedure ranked 3,025th by code quality, and the linter's top hits had never executed. Reviewing in linter order means spending the quarter on dead code.

  • Parses every T-SQL module with ScriptDom, joins it to Query Store runtime cost, and ranks with the score breakdown visible.
  • Static analysis is architecturally barred from marking anything critical, enforced in the type system and by a CHECK constraint. Code shape cannot see cost.
  • Read-only is proven, not asserted: least privilege, a query-only reader type, and a test that fails the build if any SQL constant parses to a write or DDL.
  • Also how I reverse-engineer an estate nobody documented. 15 databases across 4 instances in 63s, 33s incremental.

QueryLens

A code-review gate for T-SQL, plus natural language to SQL

A mechanical code-review gate for T-SQL, so standards do not depend on who is reviewing that day.

  • Analyze checks a query for the patterns that stop an index being used: a function wrapped around an indexed column, a leading-wildcard LIKE, NOT IN against a subquery. Returns a score out of 100, a grade, and the rewrite for each finding.
  • Scoring is deterministic. Same query, same grade. The model writes SQL, it never grades it.
  • Ask turns a plain-English question into SQL and runs it live. The connection executes SELECT only.

FlowLens

Write-audit-publish gate for SQL Server ETL

A stored procedure can finish with no errors, log Succeeded, and still lose a third of its rows to one bad join.

  • Loads each batch to staging and holds it until it clears three gates: declared data contracts, source-to-target reconciliation on row counts and key values, and an IsolationForest check against batch history.
  • The verdict is deterministic SQL and statistics. The LLM only writes the incident report, so it cannot declare a bad batch clean.

AuditLens

Audit evidence and access anomaly detection for SQL Server

Out of quarter-end evidence gathering at Bank of America, where producing the answer took longer than knowing it.

  • Evidence packs: a fixed query set per instance, rendered dated and mapped to the SOX or HIPAA control it satisfies. "Who could read this table in Q2" becomes a document, not an afternoon.
  • Privilege-creep inventory: diffs role membership between two packs. The finding that matters at audit is the temporary grant nobody removed.
  • Access baseline: per principal, the normal hours, objects and volume, with an Isolation Forest flagging what does not fit. A reporting account that reads six tables on weekdays starts reading a seventh at 03:00 Sunday. It has permission, so no rule fires.
